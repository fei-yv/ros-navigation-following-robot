# 故障排查与备选方案

本文汇总小车搭建与调试过程中的典型故障及处理办法，每项按"现象 → 原因 → 处理"组织，并给出可用的备选方案（Plan B）。原则：先保护人和硬件，再缩小变量；一次只改一项，并记录测试结果。任何失控迹象立即断总电源。

## 正式底板未就绪时的台架方案

在等待正式底板期间，以下工作可以在台架上先行完成：

- 在工程副本中核对 Keil VE/512KB 目标、建立本车专用参数宏、实现 300ms 安全停车。
- 单独编译和运行 Camsense X1 驱动，完成 Noetic、权限、udev、RViz 和断流测试。
- 把两电机牢固固定在临时木板/亚克力板，车轮悬空，做方向、编码器 10 圈计数、串口和断联停车测试。
- 小主机先用原适配器，C30D 单独用电池，避免把供电干扰混入底盘排障。

不能提前定案：最终轮距、承重轮径、footprint、雷达 TF 和导航参数。临时载板只用于台架，不把其尺寸写入正式配置。

备选方案：如果无法使用原厂底板，可购买/加工通用板替代，但下单前确认电机支架孔距、轮径离地间隙、电池和主机安装空间、雷达无遮挡位置及整车重心。

## C30D 的 UART3 接口与预期不符

按顺序排查：

1. 看板上接口丝印、C30D V2.0 原理图/说明书和随板线定义，确认外部数据口是否连接 MCU 的 PD8/PD9。（已实物确认：板上"与ROS主机通讯"口就是 USART3 引出，USB 数据线直插即可，勿与"一键下载"烧录口混淆。）
2. 在 Windows/Ubuntu 查看 USB 转串口桥芯片和设备枚举；不要把 UART1 烧录口或雷达串口误认为 UART3。
3. 用串口工具以 115200、8N1 观察是否有 C30D 上报帧；必要时用逻辑分析仪测 PD8/PD9 是否有数据。
4. 交叉核对 TX/RX：板 TX 接转换器 RX、板 RX 接转换器 TX，并共地；只接 3.3V TTL 信号，不接 RS-232 电平。
5. 若 PD8/PD9 有数据但外部口没有，检查连接线、桥接芯片或接口映射。

Plan B：USART1 或 UART5 在源码中也以 115200 初始化，可临时验证协议通道，但修改中断/发送路径前必须通读 `HARDWARE\usartx.c`。UART1 同时承担 FlyMcu 烧录，不能未经验证就作为永久 ROS 口。最终若改串口，需同步固件、接线与 ROS launch 配置。

## 编码器计数不是 836/圈

> **注意**：OLED 自检页只显示**实时轮速（m/s×1000）和方向符号**，没有累计计数，所以"手转 10 圈数 8360"在 OLED 上做不了。验证 836/圈最实用的办法是 **ROS 联调时的直行里程校准**（直行 1~2m 量实际距离，调 `odom_x_scale`），它同时验证编码器精度×轮径，一步到位；需要看原始计数可用 UART1 + DataScope 上位机（固件已带 `DataScope_DP`）。

1. （备用）若确实要数原始计数：UART1 接 USB-TTL 到电脑，用 DataScope 上位机看编码器原始计数，手转输出轴 10 圈，A/B 通道应约 **8360**（`11×19×4×10`）。
2. 若约为 2090/10圈，可能没有做四倍频；若约为 8360/10圈，符合 `11×19×4`。
3. 若倍率接近但不一致，核对商家所谓"11PPR"是单通道周期、边沿数还是已四倍频计数。
4. 核对实际减速箱是否真为 19:1，不能只依据同一商品页面的另一个规格选项。
5. 检查霍尔供电、电平、A/B 相接线、松动和干扰，再看编码器中断是否丢边沿。

最终以"源码中断口径 + 实测（DataScope/ROS 里程计） + 直行距离校准"共同决定参数，不为了凑 836 而盲改倍频。

## 电机方向或闭环失控

- 车轮悬空、速度限制约 0.3m/s，单通道测试。
- 若正向命令物理反转，可交换该电机动力线或在统一的方向配置处反相。
- 随后必须再看编码器反馈符号；正向目标应得到正向反馈。
- 若给很小目标却迅速满速，立即断电，优先怀疑反馈符号相反、编码器无反馈或参数尺度错误。
- A/B 两侧都正确后，再测试直行和原地旋转；最后才落地。

**用固件自检页定位编码器符号（实测有效）**：
1. 上电后 **EN 保持 OFF**（电机不转，编码器仍工作）。
2. 翻页：**长按用户按键约 1 秒**在"主界面 → 调试页 → 自检向导"之间循环；进入自检向导（0/8 请阅读手册）后**短按（单击）进入下一步**：0/8 → 1/8(确认 Diff) → 2/8(悬空提示) → 编码器页。编码器页**右下角也显示 2/8**（固件页码标签与步骤号不完全一致），上面显示 `A+/-`、`B+/-`、`C+/-`、`D+/-` 的**实时轮速（m/s×1000）和方向符号**，不是累计计数。
3. 手动把轮子往**前进方向**转：标准接法下应显示 **A+/B+**；若显示 **A-/B-**，说明该通道编码器相位反了。
4. 修法二选一：物理上交换该电机编码器 A/B 两线；或在 `balance.c` 编码器符号处（Diff 分支）翻转对应符号（本车即用此法：`Encoder_A_pr=-A; Encoder_B_pr=+B`）。
5. 修好标志：EN ON 不碰不转；手动转轮子有**刹车感**、松手自停（而不是越转越快）。

## 雷达驱动编译或运行失败

编译失败：

- 确认包没有多嵌套一层，`package.xml` 在 catkin 工作空间 `src` 下的包根目录。
- 运行 rosdep，安装 `roscpp`、`std_msgs`、`sensor_msgs`、Boost 和 RViz。
- 修正 `CMakeLists.txt` 的安装目录 `launch rviz` 为实际存在的 `launch config`。
- Noetic 使用 Python 3 工具链；驱动节点本身是 C++，不要错误地做 Python 2 节点迁移。

串口打不开：

- 用 `dmesg`/`ls -l /dev/ttyUSB*` 查设备，确认当前账号属于 `dialout` 组并重新登录。
- 排除端口被串口工具或其他 ROS 节点占用。
- 建立 `/dev/camsense_x1` udev 规则，避免与 C30D 互换。

运行后卡住/拔插不恢复：

- 当前驱动使用阻塞读取且无完整异常捕获/自动重连。临时在 launch 加 `respawn="true"` 只解决进程退出，不能解决进程卡死。
- 长期方案是在串口打开和读取处捕获异常、设置超时并关闭后重试；修改前保留原驱动副本。
- 若 0 距离在代价地图形成假障碍，先核对 LaserScan 规范和现有导航层行为，再把无效样本处理为合适的 `inf`/超范围值并测试。

## 主机电源不稳或 USB 掉线

1. 回到隔离基线：主机用原装 12V/3A 适配器，C30D/电机用电池。
2. 若此时稳定，测合并供电后电机启动瞬间的主机端最低电压和纹波；检查线径、接头、保险座和电池能力。
3. 确认主机允许输入范围后再决定直连、降压或自动升降压；VIN 直通多路板不能稳压 12V。
4. 电源线与编码器/USB 分离布线，缩短大电流回路；必要时在合适位置加滤波、磁环或独立转换支路。
5. 若只有某 USB 设备掉线，换端口/短线并查内核日志，区分供电不足、线材和驱动故障。

## 固件无法编译或烧录

- 始终保留原工程及 `OBJ\WHEELTEC.hex`；在副本改动，可快速回到原始固件状态。
- Keil 中选择 STM32F407VE 和 512KB Flash 算法，清理后全量重编译；不要以 ZG/1MB 设置生成最终固件。
- FlyMcu 使用 UART1/CH9102，确认 COM 端口、波特率、BOOT/复位操作和供电稳定。
- **实测经验**：必须勾选 **"DTR 低电平复位，RTS 高电平进 BootLoader"**；默认极性（DTR 高电平复位）会报"芯片超时无应答，无法连接"。若仍连不上，再试手动 BOOT0=1 + 复位。
- 若新固件启动失败，先恢复原 hex 验证硬件链路，再逐项加入参数修改；不要同时改串口、车型和控制算法后一起排错。
- 烧录成功不代表参数正确，必须重新执行 [复刻流程 Bringup · 阶段 3：悬空电子台架](bringup.md#阶段-3悬空电子台架)。

## 导航抖动、绕圈或撞障碍

按依赖顺序排查，不先盲调 TEB/DWA：

```text
轮子方向/编码器 → 轮径轮距 → odom → TF唯一性与时间戳
→ laser方向与offset → footprint → 代价地图 → TEB/DWA评分参数
```

- 先在 RViz 看当前实车链 `map → odom_combined → base_footprint → laser` 是否连续且每段只有一个发布者。
- 检查 footprint 是否来自本车，雷达 0 值是否制造假障碍。
- 直行距离错主要先校轮径；旋转角度错主要先校轮距。
- 当前 `navigation.launch` 默认使用 TEB；只有几何、里程计和代价地图正确后，才在 [复刻流程 Bringup · 当前 TEB 起始参数](bringup.md#当前-teb-起始参数) 内一次修改一个参数。
- 如需比较 DWA，使用 [复刻流程 Bringup · DWA 备用起始范围](bringup.md#dwa-备用起始范围) 建立独立配置，确保 TEB 与 DWA 不同时加载。

## 地图不更新或导航启动后 TF 冲突

- 建图和导航是两种互斥模式：建图时运行 `slam_toolbox_mapping.launch`；导航时先停止 `slam_toolbox`/`slam_gmapping`，再运行 map_server + AMCL + move_base。
- 导航期间 `/map` 应来自 `map_server`，不应继续变化；`map → odom_combined` 只能由 AMCL 发布，不能同时存在 SLAM 发布者。
- 若 `roslaunch` 报节点已存在，先用 `rosnode list`、`pgrep -af 'slam_toolbox|slam_gmapping|amcl|move_base'` 查重复进程，再逐个关闭旧 launch。不要用强制杀进程作为第一步。
- 若 AMCL 无 `/amcl_pose` 或 RViz Fixed Frame 为 `map` 时没有机器人，依次核对 `map_server` 是否收到地图、`/scan` 的 `frame_id=laser`、`odom_combined → base_footprint` 是否连续，以及 AMCL 参数是否与本车实际 frame 一致。
- 若 `navigation.launch` 已 include 底盘、AMCL 或 map_server，不要在其他终端重复启动；先用 `roslaunch --nodes turn_on_wheeltec_robot navigation.launch` 查看节点集合。

## 蓝牙遥控不响应

按顺序排查，不跳步：

1. **OLED 显示 "OFF" 而不是 "O N"**：C30D 使能开关 EN（PD3）未打开，电机被固件封锁。拨到 ON 即可。
2. **上电不足 10 秒**：固件设了 `CONTROL_DELAY=1000`（10 秒延时），启动后 10 秒内所有蓝牙指令被忽略。等足 10 秒再发。
3. **没有先发 `41 41` 进入 APP 模式**：只发单个 `41` 不会自动进入 APP 遥控，必须先连发两个 `41`，OLED 从 "ROS" 变成 "APP" 才算进入。
4. **JDY-31 接错线或供电不对**：VCC 必须接 **3.3V**（不能接 5V）；TX/RX 必须交叉（模块 TX → PD6，模块 RX → PD5）；必须共 GND。用万用表确认供电和连通性。
5. **波特率不匹配**：**本车最终固件 USART2 必须为 9600**（实测）。若固件被改成 115200，所有指令到单片机都是乱码，OLED 永远不显示 "APP"。模块侧如被改过波特率，通过 EN 脚拉高上电进 AT 模式，发 `AT+BAUD=4` 设回 9600。
6. **JDY-31 和手机 BLE APP 未连接**：JDY-31 是 BLE 模块，经典蓝牙 SPP APP 搜不到。用通用 BLE 串口调试 APP（如 "Serial Bluetooth Terminal"），确认连接状态灯常亮。
7. **APP 发送格式不是 HEX**：如果 APP 以 ASCII 字符串发送 "41"（两个字节 `34 31`），固件不会解析。必须用 HEX 模式发送单字节 `0x41`。
8. **电机线未接**：蓝牙指令只能改 `Flag_Direction` 和 `Move_Y`，如果电机线没接、编码器线没接，轮子当然不转。检查 Motor A/B 的动力线和编码器线是否已按线序接好。
9. **电池电压 < 10V**：`Turn_Off()` 函数会封锁所有 PWM 输出。万用表测电池端电压。
10. **`RC_Velocity` 被 Flash 异常值覆盖**：如果 Flash 中存了异常值，默认 500 可能被覆盖。源码 `balance.c:59` 从 Flash 读取，异常时回退到 500。可尝试发 `58`（加速）看是否有反应。

以上都排除后，用串口工具直接连 USART2 的 TX/RX（3.3V TTL），确认发 `41 41` 后 C30D 是否回复数据。

补充实测经验：

- **JDY-31 同一时间只能连一个手机**：BLE 串口工具连不上（连接超时）时，先彻底关闭/断开轮趣 APP，再重连。
- 轮趣 APP 摇杆**推一下**就会连续发 `0x41`，即触发 APP 模式（固件要求连续两个 `0x41`）；松手应发 `5A` 停车。固件会**锁存最后一个方向指令**，若 APP 松手没发停车，轮子会一直转——可发 `00` 强制停。
- 蓝牙链路已打通；此后若轮子疯转，**优先查编码器符号/闭环**，不要先怀疑蓝牙。

## 最小回退状态

当问题交织无法定位时，回退到：原装适配器供主机、C30D 独立电池、轮子悬空、原始官方工程副本、单个串口设备、只启动一个底盘节点。确认一个环节后再增加雷达、合并供电、落地和导航。

> 注意：UART3 断联停车测试尚未在实车复测，复刻时请按 [ros-setup · 七、联调测试与验证](ros-setup.md#七联调测试与验证) 的步骤自行确认。
